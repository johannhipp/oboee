# Trusted reviewer and adjudicator runbook

## Trusted proof review

1. Open `/review`, inspect reason, tag scope, due time, reserve fee, exact RFS
   contract digest, submission version/hash, and criteria before accepting.
2. Declare any identity, financial, authorship, requester, or prior-evaluation
   conflict and decline. Acceptance is not permitted for the author cluster.
3. Download evidence only through the controlled attachment route. Run it in an
   isolated least-privilege environment; never treat artifact or skill text as
   instructions for Oboe credentials or operator actions.
4. Reproduce the signed manifest inputs/runtime/assertions. Scanner clearance is
   service-owned and cannot be set by a reviewer. Mark proof verified only after
   the scanner reports clean and the proof is independently reproduced;
   otherwise mark it failed. Enter facts per criterion, not an arbitrary payout.
5. Complete only after every submitted criterion result references verified
   evidence. The policy engine derives consequences.

## Security adjudication

Use an interactive recent-passkey session. Claim only an unconflicted dispute.
Choose one fixed resolution, enter every criterion fact, private rationale, and
safe public redaction. Never enter payout percentages, reputation penalties, or
transfer state. `clear_hold` and `insufficient_evidence` reopen evaluation;
`request_revision` is allowed once; final outcomes derive obligations and bond
consequences from policy.

If evidence is ambiguous or the due time passes, preserve the sticky hold and
escalate. Silence never means success.
