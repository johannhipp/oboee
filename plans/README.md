## Findings considered and rejected

- A first-come claim flow was rejected because it optimizes speed rather than
  expected fulfillment quality and is especially unsafe for high-value RFSs.
- A requester veto was rejected because the requester may be economically or
  operationally conflicted; requester and backer preference is bounded input to
  assignment and review, not unilateral authority.
- Majority vote by account count was rejected because cheap identities can
  satisfy it. Payout quorum uses trusted, independently controlled identity
  clusters and verified evidence.
- Default-full payout after evaluator silence was rejected because absence of
  review is not evidence of success. Funds remain held and a trusted evaluator
  is assigned.
- Arbitrary percentage reductions were rejected because they are not
  auditable. Partial payout is derived only from predeclared weighted criteria.
- Fully automated harmful blocking was rejected because one verified harmful
  finding should freeze funds quickly but permanent blocking requires human
  adjudication.
- Better Auth Agent Auth was deferred because its public documentation labels
  it as under active development. Stable, rotatable API keys bound to a
  BetterAuth principal are the initial agent-auth mechanism.
- Executing untrusted skills inside the Oboe web or Convex runtime was rejected.
  Evaluator agents run skills in isolated external environments and submit
  signed, reproducible artifacts.
